# 全市场回测提速：并行下载 + 数据缓存

> 状态：**方案 A（并行下载）+ 方案 B（磁盘缓存）均已实现，待实测验证**
>
> 背景：全市场 5213 只股票回测，纯计算阶段约 76s（`tools_mem_bench`），但在线拉取 400 天预热数据 + 3 天原始价数据至少需要 10+ 分钟，瓶颈在 TDX 串行下载。

---

## 1. 问题定位

当前 `BacktestPanel::onRunClicked()` 的 IO 阶段：

1. 对每只股票调用 `provider->getRawBars(code, warmStart, end)`，其中
   `warmStart = start - kBacktestWarmupCalendarDays(400天)`
2. 数据到齐后再对每只股票调用一次 `getRawBars(code, start, end)` 获取 3 天真实价
3. 以上循环在**单个 IO 任务内串行执行**

实际开销估算：

- 5213 只 × 每次 `getRawBars` 至少 2 次 TDX 命令（主 K 线 + 最新 1 根补拉）
- 两轮合计约 2 万次 TDX 往返
- 单次往返 50~100ms 时，总耗时约 16~33 分钟

而 `76s` 只是 `BacktestEngine.run()` 的纯计算时间，不包含上述数据下载。

---

## 2. 目标

- 把全市场数据下载时间从“10+ 分钟”降低到 **1~3 分钟**级别
- 减少重复下载：同一只股票 / 同一历史区间在多次回测中尽量复用
- 不改变回测结果，不影响现有策略信号

---

## 3. 方案 A：并行下载（首选）

### 思路

TDX Provider 目前是**单连接**：

- `TdxProvider::executeCommand()` 持有 `mutex_` 直到 `recvFrame()` 完成
- 多个线程共享同一个 provider 时会完整串行，并行 IO 任务无法提速

因此需要**多连接**才能真正并行：

1. 创建多个 `TdxProvider` 实例（建议 2~4 个），各自连接不同 TDX 服务器
2. 把股票池按股票代码/市场切分为 N 份
3. 每个 provider 负责一份股票，在独立 IO 任务中并行下载
4. 下载结果统一写入同一个 `DataCache`
5. 用原子计数器汇总进度，UI 进度/ETA 维持现有逻辑

### 注意点

- 并发数不宜过高，避免触发 TDX 服务器限流（建议先 2 个，稳定后增加到 4 个）
- 每个 provider 需要独立 `transport_`、独立连接状态
- 失败时该分片内股票回退到备用 provider 或单个串行重试
- 保持 `InteractiveGuard` / 交互优先级语义，避免大量下载阻塞用户交互行情

### 预期收益

- 2 连接并行：约 2 倍
- 4 连接并行：约 3~4 倍（受网络/服务器限制）
- 理想情况下全市场下载可从 10+ 分钟降到 2~4 分钟

---

## 4. 方案 B：全市场数据磁盘缓存（长期收益最大）

### 思路

新增持久化缓存层，内存 `DataCache` 只作为运行期高速缓存：

1. 落盘存“日线不复权数据”，按 `code + period` 分文件或 SQLite 表存储
2. 首次下载完整历史后，后续只增量拉最新 K 线
3. 启动/回测时先读磁盘缓存，缺失或过期的股票再走 TDX
4. 缓存自动更新：策略拉取时发现本地最新日期落后于当前交易日，则补拉最新段

### 建议存储

- 轻量实现：`data/cache/` 下每只股票一个文件，例如 `raw/SH600000.json` 或二进制
- 或复用现有 SQLite `DataRepository`（`saveBars` / `loadBars` 已存在，但尚未接入 UI 流程）
- 带元信息：最后同步时间、数据源、是否完整

### 预期收益

- 第二次及以后的全市场回测无需重复下载 400 天预热数据
- 即使仍串行下载，只需增量更新，耗时大幅下降
- 离线回测 / 调试也更方便

---

## 5. 实施顺序建议

1. **先做方案 A（多连接并行下载）**：改动相对局部，立竿见影
2. **再做方案 B（磁盘缓存）**：在并行下载稳定后接入，解决重复下载问题
3. 最后用 `tools_mem_bench` 或新增基准工具验证：
   - 打印“下载耗时 / 回测耗时 / 峰值内存”
   - 对比优化前后数据

---

## 6. 验收标准

- 同一全市场回测，总耗时（下载 + 回测）明显下降
- 回测结果与当前版本一致（收益、交易明细、净值曲线相同）
- 多次回测时第二次下载量显著减少
- 行情交互请求不被大批量下载长期阻塞
- 单元测试保持全绿（484+）
